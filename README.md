# 우리의 가을, 우리의 수학여행

삼향동초 2026.11.18~20 서울 수학여행용 모바일 우선 웹앱.
기존 `dimkum47-jpg/school-webapp-template`의 정적 웹 구조와 Pages 배포 워크플로를 재사용합니다.

## 구현
- 날짜별 일정, 교사 과제 10개 + 앨범 사진 과제 9개
- 글 임시 저장(기기), 제출·수정, 외부 사진 제출 링크
- 모둠별 색·캔바 사본 연결
- 교사 현황 조회, 확인·보완 요청, CSV, 일정·공지·제출 마감·사진함 설정
- 개인별 사전 발급 Firebase Email/Password 계정(실제 학생 이메일 수집 없음)
- 교사 역할은 Admin SDK의 custom claims로만 부여. 화면 조작으로 교사 승격 불가.
- 사진 원본·base64 이미지는 DB에 저장하지 않음

## 현재 상태
`web/config.js`의 firebase는 null입니다. 현재는 기기 안에서만 저장하는 체험 모드이며 실제 학생 데이터는 전송하지 않습니다. 기존 템플릿에 있던 Firebase 프로젝트 연결을 사용하지 않습니다.

전용 Firebase 연결·계정 발급·외부 사진함·모둠별 캔바 사본 주소 설정 및 GitHub 신규 저장소 배포는 아직입니다. QR 자동 발급, 모둠 대표 제출의 모둠원 자동 반영, 데이터 일괄 삭제 UI는 후속 작업입니다. 현재 과제는 학생별로 저장합니다.

## DB 예산: 보수적 정상 사용
20명 × 20과제 × 문서당 10KiB × 인덱스 등 여유 10배 = 39.1MiB.
실제 과제는 19개입니다. 답변·피드백을 합쳐 문서 10KiB 미만이 되도록 필드와 길이를 규칙에서 제한합니다. submissions 전체 필드 인덱스를 끕니다.
- 무료 기준: 저장 1GiB, 읽기 50,000/일, 쓰기 20,000/일 (Standard).
- 하루 읽기 운영 예산: 20,000 (50,000의 40%). 학생 20명×20건×하루 5회=2,000, 교사 20명×20건×5회=2,000, 규칙 조회·설정·재시도 여유 포함.
- 하루 쓰기 운영 예산: 5,000 (20,000의 25%). 전원 20과제×하루 10회 제출=4,000, 교사 확인·설정 여유 1,000.
- 동일 문서를 덮어쓰며 변경 이력 문서를 무한 생성하지 않음.
- 서버 규칙: 알려진 미션 ID만 생성 가능, 같은 과제 60초 간격, 24시간 창당 학생 수정 30회. 삭제는 교사만 가능.
- 30회는 서버의 과도한 제출 방지 상한이며 위 5,000회 운영 예산과 다름. 모든 학생이 모든 과제를 30회 쓰면 약 12,000회에 교사 변경이 더해집니다.
- 임시 저장은 localStorage만 사용. 실시간 리스너·주기적 조회·클라이언트 가입 없음.
- Firebase 결제 플랜을 활성화하지 않습니다. 의도적 대량 읽기·관리자 스크립트·정상 사용 초과까지 무조건 무료 작동을 보장하지 않습니다. 읽기 횟수의 전역 차단은 Firestore 규칙만으로 구현하지 않았습니다.

공식 근거: https://firebase.google.com/docs/firestore/quotas

## 개발자용 연결 순서
교사에게 코딩을 요청하는 절차가 아닙니다. 권한이 준비되면 개발자가 수행합니다.
1. 새 Firebase Spark 프로젝트, Firestore Standard, Email/Password Authentication 활성화.
2. 실제 배포 도메인 허용. 가입 기능은 UI에 두지 않음. 불특정 가입자는 trip claim이 없어 DB 접근 불가.
3. 전용 프로젝트 웹 설정을 web/config.js에 입력. 서비스 계정 키는 저장소에 금지.
4. firebase deploy --only firestore --project 전용프로젝트ID 로 규칙/인덱스 배포.
5. 교사가 본인 계정을 만들면 개발자가 Application Default Credentials로 `node scripts/provision.mjs 프로젝트ID 교사이메일 12` 실행. 출력은 비공개 초대정보이므로 공개 파일·로그·채팅에 노출 금지.
6. 교사가 접속해 사진 파일 요청 주소와 모둠별 캔바 사본을 연결.
7. school-trip-seoul-2026 등 신규 저장소에 코드 반영. 기존 템플릿/마음나무 저장소는 수정하지 않음. Pages source를 GitHub Actions로 설정.
8. 실제 학생/교사 계정으로 타인 접근 거부·재접속·외부 업로드 복귀를 최종 확인.

## 검증
`npm ci --ignore-scripts` / `npm test` / `npm run test:rules`.
규칙 테스트는 demo-school-trip 에뮬레이터만 사용하며 실서비스에 쓰지 않습니다.
학생별 코드·암호와 모둠 확정 전 실제 학생 기록 운영을 시작하지 않습니다.

## 사진·보관
사진 서비스 로그인 불필요 여부와 이름·이메일 입력 요구는 실제 요청 링크로 최종 확인합니다. 사진 업로드 성공은 자동 검증하지 않으며 학생 표시와 교사 확인을 분리합니다. 영상 수합은 기본 범위에서 제외합니다.
보관 기간은 아직 확정 전입니다. 운영 시작 전 기간을 정하고 여행 후 CSV·사진을 백업한 다음 DB와 외부 사진함 양쪽을 교사가 지정한 시점에 삭제합니다. 현재 자동 삭제나 유료 TTL은 사용하지 않습니다.
