# 우리의 가을, 우리의 수학여행

삼향동초 2026 서울 수학여행용 모바일 우선 웹앱.
운영은 GitHub Pages, 여행자·제출·설정은 앱 전용 Firebase, 사진·작품 원본은 교사 개인 Google Drive를 사용합니다. Google Sheets로 이전하지 않습니다.

## 실제 상태
현재 배포는 체험 모드입니다. web/config.js의 firebase는 null이며, 기존 다른 앱의 Firebase 프로젝트를 사용하지 않습니다. 체험 기록·이름은 접속한 브라우저 안에서만 저장합니다. 실제 다중 기기 로그인·학생 기록 공유·Drive 업로드는 아직 연결되지 않았습니다.

### 구현 및 검증
- 일정·미션·날씨를 첫 화면에 함께 표시. 날씨는 기기에서 1시간 재사용하며 학생 위치를 요청하지 않음.
- 사전 발급 개인 계정으로 접속 후 첫 이름 확인. 동일 ID 유지, 이름 중복 방지, 확인 후 변경은 교사 관리. Firebase 규칙 에뮬레이터에서 검증.
- 여행자 목록, 사진 참여자 선택, 본인/참여 기록, 로그인한 여행자용 교사 공개 갤러리.
- 교사 피드백·보완·공개/비공개·졸업앨범 후보·기록 삭제·CSV, 여행자 활성/이름/모둠 관리.
- 날짜별 미션 19개. 장소 미션별 실제 이름·이유·재료·쓰임·관찰·감상 등 구분 입력.
- 컬러 헌팅은 개인 활동. 빨강/주황/노랑/초록/파랑/보라 같은 확률. 결과를 DB나 localStorage에 저장하지 않으며 새로고침 시 초기화.
- 컬러 헌팅 원본 9장 + 3×3 완성 작품 1장, 총 10장 안내. 제공된 기존 캔바는 중앙 제목+사진8칸 구성으로, 개인별 사진9칸 사본 연결 필요.
- 포즈 18종 실루엣 안내 이미지, 미리클AI 예시 문장·외부 도구 링크 입력.
- 교사 설정은 일반 입력창으로 편집. 학생 수를 14명으로 고정하지 않음. 계정 발급 기본 수는 12명, 최대20명.
- 학생 제작 박물관 퀴즈는 종이 워크북 전용. 공연 중 촬영 과제 없음. 노원수학문화관 이동12:30~13:00, 체험13:00.

### 연결 전 범위
- 파일 선택은 개수·형식·10MiB 초과 확인만 수행합니다. 파일이 전송됐다고 표시하지 않습니다.
- Drive 업로드 화면 주소·폴더·서버 권한이 준비되기 전에는 파일 업로드를 제공하지 않습니다.
- Drive 사진 미리보기, 원본9+작품1 자동 검증, 중복 업로드 방지, 원본+썸네일 분리 저장은 업로드 서버 연결 시 추가 구현/실기 검증이 필요합니다. Firebase에는 이미지 원본이나 base64를 넣지 않습니다.
- 학생Google로그인 없이 교사권한으로 저장할 업로드 서버는 교사 Google계정 최초 승인이 필요합니다.
- 교사 삭제는 Firebase 제출 기록만 삭제하며 Drive 원본은 별도입니다. 최종 보관기간을 운영 전 확정합니다.
- 개인별 접속 QR·최종 워크북 QR은 실제 계정/업로드 검증 완료 후 발급합니다.

## 폴더
교사 Drive의 상위 폴더 1개 안에 날짜별3개+여행후1개, 제출용 총4개. 폴더를 누구나편집으로 공개하지 않습니다. 업로드 서비스에서만 접근하도록 연결합니다. 링크는 개발자에게 전달해 ID를 연결합니다.

## DB 용량/조회 예산
20명×20과제×문서32KiB×인덱스등 여유10배=125MiB (무료1GiB의 약12.2%). 실제 과제19개. 이름·참여자·추가항목을 포함해 초기40MB 추정보다 상한을 확대했습니다.
무료 Standard 기준 읽기50,000/일, 쓰기20,000/일. 정상운영 예산 읽기20,000/일·쓰기5,000/일. 이름 첫 확인·멤버 권한 조회 등 추가 여유 포함. 이름/역할은 로그인 후만 읽고, 전체 실시간리스너 없음. 학생 조회는 자신의 기록20개·참여기록100개·공개갤러리100개, 교사 전체조회400개. 실제 사용자/재조회/규칙 조회가 늘면 사용량에 반영됩니다.
같은 학생·같은 미션은 하나의 문서를 덮어쓰고, 60초 재제출 간격과 24시간창당30회 제한을 서버 규칙에서 강제합니다. 필드인덱스는 ownerUid/public/participants만 유지합니다. 결제플랜·유료TTL을 활성화하지 않습니다.
공식할당량: https://firebase.google.com/docs/firestore/quotas

## 개발자 연결 절차
교사에게 프로그래밍을 요구하는 절차가 아닙니다. 권한 준비 후 개발자가 진행합니다.
1. 앱전용 Firebase Spark프로젝트, Firestore Standard, Email/Password인증.
2. web/config.js에 해당 프로젝트의 공개 웹설정 입력. 서비스계정 비밀키는 저장소에 금지.
3. firebase deploy --only firestore --project PROJECT_ID 로 규칙/인덱스 반영.
4. 교사가 본인 교사계정을 생성하면 개발자가 Application Default Credentials로 `node scripts/provision.mjs 프로젝트ID 교사이메일 학생수` 실행. 출력은 비공개 학생코드/암호. 공개로그나채팅에 노출금지.
5. 실제 학생수·명단 확인 후 계정활성/모둠정리. 개인정보는 공개소스가 아닌 Firebase에만 저장.
6. 교사 Drive 업로드서비스를 연동하고 실제사진저장·원본유지·미리보기·대용량/중복실패·권한을 테스트.
7. 실제 기기에서 최초이름등록·친구목록·참여자기록·교사공개·재접속 검증. 개인 캔바9칸사본·AI도구 주소연결.
8. 정상확인 후 QR발급·안내.

## 검증
`npm ci --ignore-scripts`, `npm test`, `npm run test:rules`.
규칙 테스트는 demo-school-trip 에뮬레이터만 사용합니다. 실제DB에는 검증데이터를 쓰지 않습니다.
초기 체험버전은 학생별하위submissions를 사용했으나 실제Firebase미연결상태에서 entries로 정리했습니다. 이미연결한 다른서비스 데이터는 자동변경하지 않습니다.
