# 우리의 가을, 우리의 수학여행

운영: GitHub Pages / 앱 내 글·여행자·설정: 앱 전용 Firebase / 날짜별 앨범 사진: 교사 Google Drive.
Firebase는 아직 미연결이며 체험 모드입니다. 학생 간 공유와 실제 서버 저장은 전용 프로젝트 설정 후 검증합니다. 기존 다른 앱의 Firebase를 사용하지 않습니다.

## 최신 활동 구성
| 활동 | 화면과 제출 방식 |
| --- | --- |
| 국립중앙박물관 | 작품명·내가 붙인 이름·이유, 정확히 세 칸만 작성 |
| 페어플레이 그라운드 | 문장 완성형 두 칸, 완성 문장 미리보기와 예시 |

| 돌아오는 길 | 베스트 사진+제목·선정 이유·친구에게 전하는 말을 패들렛에 게시 |
| 여행 후 | 미리클AI 스티커 디자인·실제 제작 안내·드라이브 버튼 |
| 날짜별 앨범 사진 | 설명과 드라이브 이동 버튼만. 중복 입력·첨부·참여자 선택 없음 |

패들렛은 사용자가 제공한 동일 게시판을 사용하며 장소별 제목 접두사로 구분합니다. 앱은 패들렛에 자동 게시하거나 완료 여부를 확인하지 않습니다.
앱 안의 새 글쓰기 기록은 박물관·페어플레이·연극 3개입니다. 이전 버전의 다른 기록은 삭제하지 않습니다.
사진 포즈18종은 사진 메뉴에서 자체 실루엣 이미지로 확인하고 확대할 수 있습니다.
연극 문장 수는 .?! 등 문장 종료 부호로 셉니다. 문장 내용에 대한 자동 평가 기능은 없습니다.

## 데이터·권한
사전 발급 개인 Firebase 계정, 최초 이름 확인, 중복 방지. 확인 후 이름/모둠/활성 상태는 교사가 관리합니다.
본인 기록과 참여 기록, 교사가 공개한 갤러리는 로그인한 여행자에게만 표시합니다. 일반 웹 방문자에게 Firebase 기록은 공개하지 않습니다.
교사는 피드백·보완 요청·공개·앨범후보·CSV·제출기록 삭제를 할 수 있습니다. 실제 사진은 패들렛/Drive에서 별도 관리합니다. Firebase 기록 삭제는 외부 사진을 삭제하지 않습니다.
학생 수는14명 고정이 아니며 발급 스크립트 기본12명, 최대20명입니다.
색 뽑기는6색 같은 확률이며 DB/localStorage에 저장하지 않습니다. 새로고침 시 초기화됩니다.

## 비용과 검증
이미지 원본·base64는 Firebase에 넣지 않습니다. 보수적인 최대 저장량은20명×20과제×32KiB×10배여유=125MiB. 무료1GiB보다 낮은 예산입니다. 현재 새글쓰기 과제는3개로 실제 운영량은 더 적습니다.
같은 미션은 덮어쓰고60초 재제출 간격,24시간 창당30회 상한을 규칙으로 강제합니다. 읽기20,000/일·쓰기5,000/일을 정상운영 예산으로 삼으며 실제 사용량을 확인합니다. 결제플랜·유료TTL은 활성화하지 않습니다.
날씨는 학생 위치 권한 없이 서울 좌표를 사용하고 기기에서1시간 캐시합니다.
`npm test`, `npm run test:rules`로 데이터 모델/권한 규칙을 확인합니다. 실제 학생 로그인·외부 제출·휴대전화 실기는 전용 서비스 연결 후 최종 확인합니다.
Pages 자동배포는 모든 로컬JS모듈에 커밋 버전을 붙여 오래된 미션 안내가 섞이지 않게 합니다.

## 개발자 연결 절차
교사에게 프로그래밍을 요청하는 절차가 아닙니다. 권한 준비 후 개발자가 수행합니다.
1. 전용Firebase Spark프로젝트, Firestore Standard, Email/Password인증과 공개웹설정 연결.
2. `firebase deploy --only firestore --project PROJECT_ID`로 규칙/인덱스 반영.
3. 교사 본인계정 생성 후 Application Default Credentials로 `node scripts/provision.mjs 프로젝트ID 교사이메일 학생수` 실행. 출력학생코드/암호는 비공개 보관.
4. 교사 설정에 날짜별Drive/업로드주소·개인캔바사본·AI링크 입력.
5. 실제 명단·모둠을 정리하고 외부 제출/공유/권한/모바일 동작을 검증한 후 QR배부.
보관기간은 운영 전 확정하고 외부서비스와 Firebase 각각 관리합니다.
